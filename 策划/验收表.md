## 驱动环境（可复现）

- 工程：`client`
- CLI 一律**先 `cd` 进工程**再跑（否则 `unity status` 空表 / `AMBIGUOUS_EDITOR`）
- **改代码后的编译**：`unity command recompile` → 轮询 `unity command recompile_status`（`idle|triggered|compiling|completed|up_to_date`）
 —— ⛔ **本工程 Pipeline 没有 `refresh` 命令**（`unity command` 的实际命令表里只有 `recompile` / `recompile_status`；
 `refresh` 会直接报未知命令）。`recompile` 支持失焦/最小化时工作。
- **进 Play 的固定顺序**（`⛔ 顺序不能换`）：
 1. `unity command editor_stop`（先停，保证冷启动）
 2. `unity command clear_console`（清日志缓冲：日志缓冲只保留当前这一点）
 3. `unity command editor_play`
 4. **先跑** `unity command run_script --file <署名驱动> --entry Byline.Api.Cfg`（驱动为一次性脚本，放 `.ai-tmp/test/`）
 —— 它把 `Application.runInBackground = true` + `QualitySettings.vSyncCount = 0` + `Application.targetFrameRate = 60`
 打开，**并设好 InputSystem**（`InputSystem.settings.backgroundBehavior = BackgroundBehavior.IgnoreFocus` +
 `editorInputBehaviorInPlayMode = AllDeviceInputAlwaysGoesToGameView`；缺键盘/鼠标时 `InputSystem.AddDevice<Keyboard>()` / `<Mouse>()`）
 （≈skill P-2「失焦不 tick」的对策），并回打一行 `[BYLINE] CFG runInBg=1 vSync=0 targetFps=60 focused=…`。
 **取值 = 上列三项 + InputSystem 三项**（`runInBackground` / `vSyncCount` / `targetFrameRate` / `backgroundBehavior` / `editorInputBehaviorInPlayMode` / `AddDevice<Keyboard|Mouse>()`）。
 后台 / 帧率三项的等价独立片段在 `tools/probes/interact/p_runbg.cs`。
 **不先跑这条：编辑器一失焦游戏循环就停，截图/探针全都不动**。
 5. 再跑的一次性探针（放 `.ai-tmp/test/`，用完删）
- **探针/脚本/截图一律放 `.ai-tmp/test/`**（全局 skill §1.8；**长期驱动脚本**落 （`run_script`）或
 `tools/probes/interact/`（`eval_file`）—— **本工程没有 `client/_dev/` 这个目录**，它已删除），
 执行方式 `unity command run_script --file <path> --entry <类.方法>`（或 `eval_file --file <path>`）
- ⚠️ **`eval_file` 常回报 `Main thread operation timed out after 5000ms` —— 这不代表代码没执行**：
 实测该回报出现时代码**已经跑完**，只是返回值没能及时回传（主线程被 Play 循环占着）。
 **判据不是返回值而是产物**：探针里写一个文件（例 `.ai-tmp/test/<名>.txt`，即 `Application.dataPath + "/../../.ai-tmp/test/<名>.txt"`），
 然后读该文件 / 看 `unity command console --tail 50` 里的 `[探针tag]` 行 ⇒ 有行就是执行了。
 （超时后可再 `eval_file` 一次做幂等重试；探针一律写成**幂等**。）
- **截图（Overlay UI 必看这条）**：`unity command capture_game_view --source screen --save_path .ai-tmp/screenshots/<名>.png`
 * `--source screen` 抓的是**合成后的 backbuffer**（含 Screen Space - Overlay 的 Canvas）；
 `--source camera`（默认）**抓不到 Overlay UI**，HUD/商店/背包全是空白 —— 别用它验 UI。
 * **抓之前先触发一次 UI 变化**（例：`Game.Event.Emit(Events.PanelToggleRequest, "InventoryPanel")`
 或让 HUD 刷新一次）：Overlay Canvas 在「本帧无变化」时可能还没合成，抢拍会拍到上一帧/空白。
 * Play Mode 之外不能抓 `--source screen`。
- **多 agent 共用同一个 Editor / 同一个 Play**：探针必须**幂等**（重复执行结果一致，不叠加副作用）+
 **状态重试**（`editor_status` 不是 Play 就再 `editor_play`；面板没开就先 `Game.UI.Open` 再断言）。
 同一时刻**只许一个 agent** 在 Play 里跑探针（互斥靠"先 `clear_console` 再读 `console --since`"自证）。
- 离线自检宿主（秒级、非 Unity 进程，**优先用它做回归**）：`tools/probes/hosts/<name>check/`（`dotnet run -v q --nologo`），
 一键全跑 `tools/probes/hosts/run_all_hosts.ps1`。⚠️ **宿主就在 `tools/probes/hosts/`**（实测 14 个 `*check` 宿主）；`.ai-tmp/hosts/` 只剩 3 个历史目录（`appflowcheck` / `meleeshape` / `uicheck_r1c`），**不是**现行落点。
