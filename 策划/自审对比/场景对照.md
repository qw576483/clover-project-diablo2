# 场景对照 —— 三个场景 vs 原版《暗黑破坏神 II》Act I

> 对照口径：三个场景都按**原版 DS1 逐块精确拼装** —— 罗格营地必须有方形围栏合围 + 内部物件照 DS1 + 营地外的河流（水 = 阻挡）；
> 野外/洞穴按"**块与块按出口拼接**"（不是逐格随机）；随机性口径 = **块的组合顺序与出现与否**；
> 对照图**同机位**拍摄，逐项写 `一致` / `不一致（差在哪）`。

## ② 逐项对照（6 个维度 × 3 个场景）

### 2.1 罗格营地（固定布局）

**四个块的关系（实测反推，生成器每次自己复验）**：
四块 `TownN1/E1/S1/W1` **都是同一座营地**，只是**导出时的原点不同**。
锚点 = 营地围栏环左上角，独立复验 = `BARRACKS/warp.dt1` 的 3 个标记格 ——
对齐后四块的 warp 标记格**逐格重合（4/4 块通过）**，实测偏移（相对 `TownW1`）：
`TownN1 (+14,-11)`、`TownE1 (+18,-5)`、`TownS1 (+14,+6)`、`TownW1 (0,0)`。
⇒ 合并口径 = **参考块第一、其余按 `LvlPrest` 顺序逐格补空**（`FillBlanks=1` 的语义；
⛔ 是**逐格**补空不是逐层补：逐层补会让别的块的错位墙填进参考块的空地、**把出城口堵死**）。

## ③ 仍未做到"一致"的项（**列全，别挑**）

1. **野外的随机是"块级"的近似（允许的差异，登记 E14）**。
   **本项目实际口径**（`Module/Map/MapGenWilderness.cs` + `tools/d2codec/export_wild_layout.py`）：
   | 环节 | 本项目怎么做 | 引擎（`DrlgType=3`）真实过程 |
   |---|---|---|
   | 场地尺寸 | 每轴 6..10 个 8 格块（48..80 格），`rng.Next` 抽 | `Levels.txt` 固定 80×80（10×10 块） |
   | 基底 | 每格一张原版 `TOWN/floor.dt1` 草地瓦片（随机变体） | 引擎先按 lvltype 铺满地板 |
   | 周圈 | 4·cells−4 个槽位，每槽在 **42 块原版边界/崖壁块 × 左右翻 × 上下翻**里按 `OpenN/S/W/E` **四条件精确匹配**（朝外闭 + 沿环开 + 朝内开），蓄水池抽样；匹配不到 ⇒ 放宽为"朝外闭"+ Warn | `AddAct124SecondaryBorder` 按 lvltype 的 dt1mask 铺崖壁，再 `SpawnOutdoorLevelPresets` 按每格的 junction/出入口标志 + **seed 抽样**放边界预设（`OutPlace.SpawnOutdoorLevelPresetEx`） |
   | 内部 | 目标覆盖 **35%**（`FillCoverage=0.35`，写死）⇒ `want = max(2, round(interior×0.35/4))`，在内部格随机撒 16×16/16×8/8×16/8×8 的原版填充块，**只挑四边全开的块**、不覆盖纯可走格 | 内部按 `LvlSub` 的**替换组**逐格抽样（每组有 `Dt1Mask` + 密度/概率），是**逐格**随机而不是块级 |
   | 散落件 | `LvlSub` Type=6 的 6 种块里随机撒 **3..8 件**（叠加盖章） | 同样是 `LvlSub Type=6`，但逐格概率与组顺序由引擎的替换表决定 |
   | 土路 | 回城口 →（**拐一次**）→ 洞穴口，3 格宽，铺原版泥土瓦片 | `BuildExitPointArray` + `BuildVertexPathsWithJitter`（出口点之间**走真正的寻路** + 抖动） |
   | 洞口 | 洞穴口那一"行"块换成 `Act 1 - Cave Entrance`（`CAVES/CaveDr1/2.ds1`） | `SpawnTownTransitionsAndCaves` 里的 `SpawnPresetFarAway`（**放在离城镇最远处**） |
   | 可复现 | 块选择/镜像/散落件位置/路拐点全走注入 `Rng`：**同 seed ⇒ 同图** | 引擎走 `pLevel.sSeed`，同样按 seed 可复现 |
   ⇒ **差距的准确表述**：**逐格瓦片是原版的**（每格地面/物件键都来自原版 ds1），**块的选择策略是近似的**
   （"按开口拼接"的确定性规则 + 固定覆盖率，而引擎是"逐格替换组 + seed 抽样"）。
   要 1:1 复刻引擎的 `DrlgType=3` 需要把 `d2-drlg` 的户外生成器整段移植过来（那是独立的一揽子工程）。
   本项**登记在** `策划/验收表.md` 的「允许的差异」**E14**。

## ④ 河面处置与差异登记

> 范围：`Module/Map/MapView.cs`（wall 层**平色**水墙瓦片**白名单不叠**）+ `Module/Player/PlayerModule.cs`（点不可走格 ⇒ **最近可走格回退** ≤2 格）。
> ⛔ **逐格瓦片键与可走性判定一格未动**（营地仍是原版 56×40 的逐格键、河仍是阻挡、桥面仍可走）。

### 4.1 现象 → 根因（实测，不是推断）

| 项 | 值 | 判据 |
|---|---|---|
| "蓝条"到底是什么 | `Objects/moor_river/028` —— `river.dt1` 的 **wall 层纯色瓦片** | 逐键扫描**全部 295 个被引用键** ⇒ **唯一色数 = 1 的平色瓦片只有这一个**（RGBA(0,32,68)），铺在河带 x=47/54 共 **49 格** |
| 为什么静态看像占位 | 原版靠 `ACT1/Pal.PL2` 的**调色板循环**把这张平色瓦片变成水面动画；本工程**没有运行期调色板循环** ⇒ 静态 = 硬边平色块 | 同上脚本（平色 = 像素无变化） |
| 排除「Exit 亮青占位」 | 取不到文件的键 = **0** ⇒ `GroundColor(Exit)` 亮青 (0,217,255) 在营地**无处触发** | 同上脚本第 ③ 项 |
| 排除「半格错位」 | 逐格键与 tile 中心对齐逐格核对无偏 | 同上 |
| 桥为什么"走不上" | `PlayerModule.MoveTo` 对**不可走**目标**直接拒绝**，而桥栏杆与桥面**相邻 1 格** ⇒ 点到栏杆整次点击作废（视觉误点） | 实机 `[R1-B]` 回退日志 + `playercheck::Step4_Unreachable` / `Step4b_BridgeWaterFallback` |

### 4.2 处置

| 处置 | 口径 | 为什么这样 |
|---|---|---|
| **wall 层平色水瓦片不叠** | `MapView` 内一张**只含 1 个键**的白名单（`moor_river/028`）；命中即跳过壁层叠图，floor 水瓦片照旧铺 | 引擎无运行期调色板循环 ⇒ 该瓦片静态渲染**必然**是硬边平色块（观感等同占位）；登记 **E32** —— 做出运行期循环后**清空白名单即可，逻辑零改动** |
| **点不可走格 ⇒ 最近可走格回退** | 仅「图内但不可走」回退，半径 ≤ 2 格（Chebyshev；按 ① 离点击点最近 → ② 离角色最近 → ③ (dx,dy) 升序 **确定性**取格）；**图外一律拒绝**；半径内无可走格 / 走不到 ⇒ 仍按不可达拒绝 | 原版 D2「点不可走处 ⇒ 走向最近的可走处」；桥栏杆紧邻桥面，误点概率高 |

### 4.3 差异登记

- **E32**｜河面 wall 层纯色水瓦片（49 格）不叠 —— 「是什么 / 为什么必须这样（实测证据）/ 出处 / 何时能消除」四要素见 `策划/验收表.md`「允许的差异」**E32** 行。
- 本项**不影响**营地的「关卡尺寸 / 方形围栏合围 / 内部物件 / 营地外的河 / 木桥 / NPC 站位 / 明暗」七维结论：
  那些逐格键与可走性**一格未动**，`tools/probes/hosts/mapcheck` §10 / §15 全绿（含"桥面 20 格全可走 /
  栏杆 20 格全阻挡 / 出生点能走到河东岸"与"平色水墙瓦片不叠：白名单恰 1 键 / 命中 49 格全在 x=47,54 /
  这 49 格仍是水=阻挡"）。
