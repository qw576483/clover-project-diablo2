## 8. 需主 agent 裁决 / 需返工清单（按严重度）

### A. ★★★ 玩家无法主动攻击、没有交互光标（会影响交付）

- **现象**：`Events.AttackRequest`（参数 int monsterId）**全工程没有任何发送方**
  （grep 全量：只有 `CombatModule` 订阅它、`Module/Input/InputReader.cs` 只发 `UseBeltRequest`）。
  同理 `Events.HoverTargetChanged` / `Events.CursorChanged`（`Def.HoverTarget` / `Def.CursorKind` 已定义）
  **也无人发送** ⇒ 步骤文档 §1「② 操作与相机 → 交互光标」这一项没有任何执行者。
- **影响**：左键点怪不会攻击（`ICombatModule.RequestAttack` 只有 UI/输入侧才可能调到）；
  验收表里"战斗闭环"相关行在 Play 里必然过不了。
- **为什么 App 层不做**：它需要「鼠标屏幕坐标 → 相机反投影 → 命中哪只怪」的拾取，
  属**输入/视图职责**（`InputReader` 已有 `HoverGrid`，但没产出 `HoverTarget`），
  在 App 里实现等于把业务写进装配层（也违反"不许改模块实现逻辑"的等价精神）。
- **建议**：激活原 agent-06（`Module/Input`）补一个"悬停拾取 + 左键派发"的接线点：
  悬停怪物 → `IMonsterModule.SetHovered(id)` + 发 `HoverTargetChanged`；
  左键点怪 → 发 `AttackRequest`；或者由 agent-09 在 `HudPanel` 里做（HUD 是 Stage 常驻）。
- **参考**：`ItemModule` / `NpcModule` 已经为"点击地面物品/点击 NPC"做了 `MoveCommand` 兜底
  （注释写着"没人发 `PickupRequest`/`NpcInteractRequest`"），**唯独攻击没有兜底**。

### B. `D2.Player.Revived` 的**发送方**缺失（常量已补，App 临时补发）

- `ICombatModule.RevivePlayer()`（`Module/Combat/CombatModule.cs:401`）与 `IPlayerModule.Revive()`
  **都不发** `Events.Revived`。
- 本轮的处置：`App/AppEventRouting.cs` 在 `ReviveRequest` **被 CombatModule 处理完之后**，
  且玩家确实 `IsDead == false` 时才广播 `Revived`（本层能观测到 `PlayerDied`，可判"是不是真复活"）。
  这是**临时发送方**，建议原 agent 在 `RevivePlayer()` 里直接 Emit 后去掉这段。
- 断言证据：`[Assert] 玩家已复活（IsDead=false）⇒ 广播 D2.Player.Revived`（离线宿主本轮未触发死亡，故只在代码层登记）。

### C. `D2.Item.MoveInInventoryRequest` 无法落地（**契约层裁决**）

- `IItemModule`（契约冻结）**没有** `Move/Swap`，`Module/Item/Inventory.cs` 也未对外开放移动
  （`UI/InventoryPanel.cs:551` 同样记录了这个缺口）。
- 裁决二选一：① 给 `IItemModule` 加 `bool MoveItem(int fromAnchor, int toAnchor)`（需改契约）；
  ② 由 UI 侧改成"取出到地面 + 再拾取"两步走（不必改契约，但手感差）。
- 当前行为：App 收到该事件只打一条可定位 Warn（**不假装成功**）。

### D. `UnequipRequest` / `ShopOpenRequest` 常量与转发已备，但 UI 侧仍未 Emit

- `UI/InventoryPanel.cs:472-478` 目前是"点击装备槽 → Warn + Toast「卸下装备暂未接线」"，
  **没有 Emit** `Events.UnequipRequest`。因为本 agent 不许改 `UI/**`，
  所以**在 Play 里点装备槽仍然不会卸下**（虽然 App 侧的接收端已经就绪）。
- 建议：激活原 agent-09，把那两处 Warn 换成 `Game.Event.Emit(Events.UnequipRequest, packed)`；
  `ShopOpenRequest` 同理（当前商店靠 `NpcModule.ChooseOption` 的"商店入口"选项打开，已可用）。

### E. `MiniMapPanel` 首次打开拿不到地图数据（HUD 传 `null`）

- `UI/HudPanel.cs:671` 是 `Toggle<MiniMapPanel>(null)`，而面板是在 `OnOpen` 里才订阅 `MapGenerated`
  ⇒ 刚打开的那一个收不到任何快照，会显示"自动地图（无数据）"。
- 本轮的处置：`AppSnapshots` 在收到 `MiniMapPanel` 的 `PanelToggleRequest` 时
  ① 立即发一次（刷新已打开的面板）② 用 `Game.Timer.AfterUnscaled(0.05s, …)` **下一帧再发一次**
  （那时面板已完成 `OnOpen` + 订阅）。
- 建议：agent-09 让 HUD 缓存 `MinimapArgs` 并像别的面板一样传进去，之后可删掉这段兜底。

### F. `AppWiring` 用反射调 `AttachRoot` 而非类型转换（**已做，说明理由**）

- `AttachRoot(Transform)` 是**非契约**入口。若 App 层写 `ctx.Map is MapModule`，
  App 就**编译期依赖** `Module/Map`、`Module/View`；
  而 `.ai-tmp/hosts/flowcheck` / `.ai-tmp/hosts/uicheck` / `.ai-tmp/hosts/combatcheck` 是"只编子集"的宿主，
  会让它们的构建失败（agent-06 在回报里已遇到过同类问题）。
- 反射 + 明确的失败日志（找不到方法 / 调用抛异常都带类型名与参数）与本项目
  `AppContext.AutoWire()` 的装配哲学一致，且六个宿主全部零错回归。

### G. 可选：战争迷雾 / 已探索标记尚未在进图时打开

- `IMapModule` 上没有雾的开关，`MapModule.SetFogOfWar(bool)` 是非契约入口。
  当前 App **没有**在 `StageEntered` 调它（= 迷雾默认关闭，`MarkExplored` 仍在随
  `PlayerGridChanged` 累积）。原版 Act I 的野外/洞穴有暗区，如果验收表要求"黑幕未探索"，
  请在 App 侧加一行 `SetFogOfWar(true)`（我可以补，或由主 agent 裁决是否是本轮范围）。

### H. 契约口径备忘（不需改代码，建议写进 `docs/步骤文档.md` §2）

- `Def.AreaId` = **0 基**（Town=0/BloodMoor=1/DenOfEvil=2），`level_c.id` = **1 基**
  ⇒ 跨表一律经 `AreaLevelTable.Resolve`（见 §4-8）。
- `IItemModule.DropLoot(int treasureClassId, …)` 的 `int` = `Treasureclass.All()` 的 **1 基行序**（见 §4-9）。
- `Events.UnequipRequest` 的 int 打包 = `((int)ItemSlot & 0xFF) | (slotIndex << 8)`；
  `Events.MoveInInventoryRequest` 的 int 打包 = `fromAnchor | (toAnchor << 16)`（本 agent 新增，已在常量注释里写明）。

## 9. 已知边界（不是缺陷）与不在本轮范围

- **渲染层无法离线驱动**：`new GameObject()` / `new Texture2D()` 在非 Unity 进程抛
  `SecurityException: ECall methods must be packaged into a system module`
  ⇒ 离线宿主里 `MapModule.ShowArea` 与 `ViewModule` 的节点创建必然走降级分支
  （`ViewModule` 自己 catch 并置 `_cannotRender`，日志 `本进程不具备渲染能力`）。
  宿主把这类调用**隔离+记录**，不假装成功；**渲染/像素/手感仍必须让主 agent 进 Play 验收**。
- **`AppFlow` 的菜单链路**（Boot→MainMenu→选角→创角→Loading→Stage→Pause→回主菜单、清场 7 项）
  由 `.ai-tmp/hosts/flowcheck` 覆盖（本轮回归通过）；fullcheck 覆盖的是**模块级全链路 + App 层接线**，两者互补。
  （原因：`AppFlow.OnEnterStage` 会调 `Map.ShowArea`，离线进程必抛 ⇒ 无法在 fullcheck 里让 Flow 走到 Stage。）
- **UI 面板实例**：离线宿主里 `IUIManager.Open<T>` 是替身，不实例化 MonoBehaviour
  ⇒ 面板内部构件、像素布局、`Time.timeScale=0` 下的 `AfterUnscaled` 仍待 Play 实测。
- **用户尚未打开 Unity 编辑器** ⇒ 本轮**没有**跑 `unity run/test/batchmode`；Play 实测留给主 agent（闸门 2）。
- 不在本轮范围：Act II~V、雇佣兵、符文之语、赫拉迪克方块、专家模式、Battle.net 联机（与步骤文档 §1 一致）。
